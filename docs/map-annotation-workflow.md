# マップ注釈の登録・検証手順

## 目的

マップ画像に印字された脱出地点名を読みやすいまま強調し、画像更新後の座標ずれを配布前に検出する。

## 注釈モデル

脱出地点ごとに次の情報を分離して扱う。

- `labelBounds`: 画像に印字された文字を囲む矩形。複数行・分割表記は複数矩形にする。
- `focusPoint`: 地点選択後に画面中央へ移動する基準点。
- `hitBounds`: 詳細を開くための透明なクリック領域。
- `revision`: 注釈が対応するマップ画像の版。

アプリ内部では元画像のピクセル座標へ変換する。画面サイズやズーム倍率を座標データへ混ぜない。

## 表示ルール

- 文字の内側は塗らない。
- 枠線と発光は文字の外側だけに出す。
- 見える枠とクリック領域を同じ大きさにしない。
- マップ画像の寸法が登録版と違う場合、注釈を表示しない。
- 画像に名称が印字されていない地点は明示的に未印字として登録する。

## 新しい画像へ更新する場合

1. 元画像の幅と高さを確認する。
2. SHA-256を記録する。
3. OCRで名称候補を検出する。
4. OCR結果をそのまま採用せず、人間が文字範囲と改行を確認する。
5. `labelBounds`、`focusPoint`、`hitBounds`を登録する。
6. 画像版の`revision`を更新する。
7. 全地点監査と通常表示の両方で確認する。

## 全地点監査

開発用URLへ`?mapAudit=1`を付けると、そのマップに登録された全注釈を赤い点線で一括表示する。

確認項目：

- 正しい名称だけを囲んでいる。
- 近隣の別名称を巻き込んでいない。
- 1行・2行・3行の印字範囲が一致する。
- 100%、175%、300%で文字が読める。
- 画像端で枠が欠けない。
- 通常表示では選択した地点の枠だけが表示される。
- 枠をクリックして詳細を開ける。

## 配布前の必須検査

`npm test`で、対応マップの全脱出地点が「注釈あり」または「画像に名称未印字」のどちらかに分類されていることを確認する。未分類地点が1件でもある場合はテストを失敗させる。
